# Portable evidence contract

This is the target contract, not a claim about the current implementation.

## Boundary and ownership

Every Factory-generated byte written into the committable repository must be
prepared for publication first. This includes CAS objects, structured records,
temporary publication prefixes, configuration, review responses, and derived
reports. Factory does not rewrite user source files, provider transcripts,
foreign `.factory` files, or Git history.

Private journal bytes and reviewer runtime output may remain raw under the
existing private-runtime rules. They must never be copied into `.factory` or a
review bundle without preparation. This is a committable-data boundary, not an
anonymization guarantee for the developer's machine.

One shared `@factory/sanitization` owner implements discovery, matching, and
text transformation. Provider adapters identify result blocks; they do not own
separate secret rules. The public-contract package owns portable schemas.
RepositoryStore remains the only publisher. Domain projections and bundle
verification do not consult live env files or rerun sanitization.

## Secret policy

- Use the fixed policy identifier `evidence-sanitization-1`; it describes
  transformation semantics, not an old-format compatibility path.
- Walk the repository root recursively, including ignored entries. Read ordinary
  files whose basename starts with `.env`. Never follow directory or file
  symlinks, leave the repository root, traverse submodule checkouts, or enter
  `.git`, `.factory`, `node_modules`, `vendor`, `.venv`, `venv`, `dist`, `build`,
  `target`, `.next`, `.nuxt`, `.turbo`, or `coverage` directories.
- Bound discovery by 100,000 visited entries, depth 64, 1,000 env files, 1 MiB
  per file, and 8 MiB total env input. Use descriptor-relative no-follow reads
  and detect replacement/races. These initial limits are delegated for tuning
  only with a synthetic performance probe and a recorded rationale.
- Parse assignments as data using the [research baseline](research.md). Collect
  every nonempty decoded value of at least eight Unicode code points. Also
  collect shorter nonempty values when the variable name contains `TOKEN`,
  `PASSWORD`, `SECRET`, or `API_KEY`, case-insensitively.
- Exact matching is case-sensitive and literal. Resolve overlapping matches
  deterministically, longest match first at the same position. Match decoded
  JSON text, including unknown string fields and keys; JSON escaping must not
  conceal a known value. Do not recursively decode arbitrary base64 strings.
  For quoted env values, also match their literal escaped spelling, so copied
  env-file text receives the same protection as decoded messages. Merge the union
  of overlapping matches rather than leaving a fragment of either secret visible.
- Add bounded, synthetic-tested rules for recognizable API tokens, bearer
  credentials, private-key blocks, and secret-labelled assignments. The exact
  initial provider-pattern catalogue is delegated; document tested coverage
  beside the rules. No entropy-only blanket hash removal or network validation.
- Replace matches with `[REDACTED]`, with no secret-derived identifier or saved
  dictionary. Preserve the marker as transformation syntax on subsequent passes.
  JSON key collisions caused by redaction omit the affected opaque record with
  a limitation; never silently overwrite a sibling value.

No env files is a valid empty dictionary. Unexpected unreadability, malformed
assignments, races, or exceeded discovery limits fail preparation with a fixed
reason, rather than silently publishing with an incomplete dictionary. Hooks
still return their normal successful empty response; private diagnostics retain
the failure and capture can retry. Intentional exclusions are policy, not errors.
The dictionary describes values available at preparation time: deleted historical
values and later discoveries cannot be retroactively guaranteed without history
rewriting, which is out of scope.

Preparation also bounds in-memory matching: 500,000 dictionary states, 200,000
disjoint match/marker spans, and 64 MiB per text input. Exceeding those ceilings
returns `sanitization-limit`, never partial matching. Consecutive/overlapping
matches coalesce before counting; tool-result trimming counts Unicode with a
fixed-size tail buffer rather than allocating one array element per character.

## Tool-result reduction

Redact decoded text before truncation. A recognized tool result has a retained
text budget of 4,000 Unicode code points, excluding the explicit omission marker.
If longer, retain the first 3,000 and last 1,000, separated by
`\n[Factory omitted N characters]\n`, where N counts removed sanitized characters.
For a result containing multiple text blocks, apply one budget across their
ordered concatenated text, retaining the provider's envelope and result identity.
Do not grant each array element another budget. Nontext attachments are omitted
with an explicit limitation rather than copied as opaque bytes.

User and assistant prose, including tool-call arguments, is not truncated.
Claude's user-role wrapper can contain tool results; wrapper role alone cannot
classify it. Codex function-call outputs and supported alternative result shapes
must be recognized from provider fixtures. Unknown JSON records are recursively
redacted but not guessed to be tool results. Malformed JSONL lines become fixed
omission records at the same ordinal; no raw fallback. Preserve readable sibling
lines, sequence membership, and missing-evidence limitations.

## Schemas and identity

Introduce a shared portable transformation summary: policy identifier, whether
redaction occurred, omitted character count, and fixed omission reasons. Attach
it to transformed leaf evidence and source entries through contract-owned types;
aggregate it into Turn/review limitations. Do not invent per-secret records.
Keep `ObjectRef` as the exact-byte reference it is today; transformation metadata
belongs on its containing evidence envelope, source entry, or owning record,
not on an alternative reference type that changes citation inventory equality.
Rename public `raw`/`rawObjects` fields that now refer to transformed evidence to
`evidence`/`evidenceObjects` and update every producer, parser, and consumer in
the same owning slice. Private journal `raw` retains its literal meaning.

Object digests and lengths describe exactly the sanitized stored bytes. Build
parent records, inventories, manifests, fingerprints, and citation authority
after those references exist. Typed Git SHAs, CAS references, and Factory-generated
IDs are structural and unchanged; arbitrary prose that resembles a hash has no
structural exemption. A known env value matching a typed SHA still does not
invalidate that SHA field.

Do not add public digests of unsanitized payloads as redaction provenance: they
can act as guessing oracles. Existing structural Git/CAS identities remain under
the explicit exception above; raw-to-prepared claim linkage stays private.

Names and paths are not automatically safe structural hashes. Inspect decoded
Git path bytes as well as display strings; omit a source entry whose path cannot
be retained safely, without saving its encoded original in a limitation. A
required operational locator or config value that would be altered is refused
with a fixed reason rather than silently redirected. Optional descriptive fields
may be redacted or omitted. Do not create a parallel pseudonymous path namespace.

Source objects are sanitized UTF-8 review snapshots, not promises of runnable or
byte-identical source. Never import `.env*` contents themselves, even when tracked.
Omit unsupported binary/invalid-UTF-8 source, unsafe symlink targets, and nontext
attachments with fixed reasons. Ordinary textual symlink targets may be retained
only unchanged. Redacted patches remain review context, not guaranteed applicable
diffs. Preserve newline structure where practical, but citations refer only to
the final sanitized representation.

Keep original Git observation/race authority separate from sanitized content
identity. Two distinct raw code states can sanitize identically; this must not
establish exact continuity or incorrectly skip a review. Reconstruct and verify
the sanitized manifest without consulting live source or env files.

## Durability and failure

Freeze sanitized publication bytes privately before the first committable write
of a recoverable group. Extend the existing journal/attempt owner with this
preparation, not a new general transaction service. Store the safe bytes,
references, fixed policy metadata, and binding to the original claim membership;
never store the secret dictionary. Replays use that preparation unchanged, even
after env rotation, and preserve existing trigger/manifest-last publication.

Before durable preparation completes, failure leaves no committable prefix and
retry may use the currently available env values. After it completes, retries
do not regenerate bytes under an existing immutable identity. Completion proves
the portable graph against the frozen preparation, not equality with raw journal
hashes. Check transcript lag/completeness on the original observations before
transformation and freeze those findings with the prepared evidence.

Unsupported individual evidence can be explicitly omitted while readable
remainder is reviewed as partial. Sanitizer/discovery failure is different: no
raw fallback or misleading claim of successful protection. Partial evidence
still gets a best-effort review under existing coverage semantics; deterministic
redaction/trimming must not cause an endless automatic re-review loop.
