# 4 — Review output, actions, and publication closure

Depends on slice 3.

## Contract and seam

Sanitize model response text and validated prose before final ledger/entry
identities and publication. Keep validated structural citation references; resolve
locators only against sanitized bundle evidence. A locator that cannot remain
valid is rejected under the existing invalid-output/partial acceptance policy,
not silently remapped to unrelated evidence. Malformed response tails must not
leak through the saved response copy.

Update the pinned reviewer prompt/policy identity to explain redaction and
omission markers and the sanitized-source contract. Changing the env dictionary
can legitimately change a newly acquired sanitized subject; an unchanged prepared
subject still obeys existing incremental no-op rules.

Prepare human decision and coverage actions before semantic comparison, derived
fingerprints, and append. Retried immutable identities must return their prepared
semantics rather than recomputing different bytes after env changes. Extend the
existing attempt/action owner where a frozen preparation is necessary; do not
introduce a general transaction framework.

Close the repository admission contract: CAS, immutable creation/groups, review
publication/imports, configuration, actions, and Factory-generated reports may
accept only prepared content or structurally validated data with no unprocessed
free text. Make this a real API boundary, not a caller convention. Existing safe
references can be reused without requiring an env dictionary at read time. Do not
transform serialized manifests after their identities were computed.

Inventory every writer and remove temporary unrestricted raw-byte entry points
from earlier slices. Policy cannot be disabled by configuration. Refuse required
configuration/locator values that preparation would corrupt. Preserve foreign
user-owned files without interpreting or claiming to sanitize them.

## Red/green and inspectable result

Pin response/ledger copies, invalid output tails, PR evidence imports, prior
ledger bundles, user explanations, JSON keys, and config strings with synthetic
sentinels. Exercise real RepositoryStore in Docker even when model/gh boundaries
are fixtures. Verify citation resolution, decision compare-under-lock, idempotent
retries after env rotation, and unchanged structural IDs.

Add an admission test covering each public mutation surface: raw input cannot
bypass preparation, while sanitized graphs verify without live env access. Keep
readable partial reviews and incremental no-op behavior green; ordinary reduction
must not create an automatic retry loop.

Extend the review/decision workbench report with sanitized output and an accepted
human action. Record invocation and verdict. No UI redesign is in scope; if
implementation changes visual presentation, invoke the project's visual skills
and gates before accepting it.
